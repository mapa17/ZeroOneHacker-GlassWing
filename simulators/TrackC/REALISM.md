# Realism model — UNIQA Coach

> **⚠️ Outdated in parts.** The probabilistic **batch simulator** described throughout this
> document (`personaSimulator.js`, `profileToSim.js`, `profileFormFill.js`, benchmark
> validation, `test:personas` / `test:agent` / `validate:benchmarks`, the Statistik-Labor
> tab) has been **removed**. The funnel is now exercised in only two ways: the **LLM
> customer simulation** (`npm run agent:interactive`) and a **human clickthrough** of the
> web app. Sections below about calibrated dwell/continue distributions, large-N runs, and
> benchmark tolerances no longer apply. The parts about the **interactive agent**
> (profile→prompt→agent loop, trace files, exit types, validation feedback) are still
> accurate. See `CLAUDE.md` and `SETUP.md` for the current flow.

This document explains what is **realistic** vs **synthetic** in session exports, and how the four realism improvements work together.

## What is realistic

| Layer | Source | Realism |
|-------|--------|---------|
| **Segment mix** | `personas.json` → `online_funnel_traffic_share` (30/50/20) | Matches UNIQA online-funnel visitor split |
| **Persona profile** | `PersonaSampler` from population distributions in `personas.json` | Each person has coherent age, income, drivers, online behaviour |
| **Aggregate funnel stats** | Calibrated `sim` blocks + benchmark validation | Large-N runs target ~66% / ~24% / ~78% gate drops, ~5.6% conversion |
| **Form field values** | `profileFormFill.js` — derived from profile (not placeholders) | Birth date matches age, tariff leans on income/drivers |
| **Behaviour modifiers** | `profileToSim.js` — online comfort, age, switch willingness | Same segment, different people → different dwell/hover patterns |
| **Agent tab runs** | Real browser funnel + Claude form fill from UNIQA profile | Genuine UI interaction; LLM decides tariff/addons as the person |
| **Classifier** | Same rules on live and simulated sessions | Consistent “who is this user” read across modes |

## What is still synthetic

- **Mouse telemetry in batch tests** (`npm run test:personas`) is generated by `personaSimulator.js`, not recorded from a browser. Timing follows calibrated distributions, not real DOM events.
- **GPT enrichment** (`--gpt`) adds narrative only; it does not drive hover counts or cursor paths.
- **Classifier accuracy ~90% on sim data** is partly circular — simulator hypotheses overlap with classifier signals. Real sessions may score lower until recalibrated on production data.
- **Drop-off probabilities** are segment-level hypotheses, not individual propensity models fitted to real user IDs.

## Four realism improvements (implemented)

### 1. Profile → behaviour link

**Order:** sample profile → `buildSimFromProfile()` + `formFillFromProfile()` → `simulateSession()`.

A 66-year-old Judith with low online comfort gets longer dwell on personal data, more back-presses, and lower continue probability than a 28-year-old Franz who buys insurance online.

### 2. Real agent runs

- **In-app:** Agent tab loads segment personas from `personas.json`, Claude fills the live form as that person.
- **Batch:** `npm run test:agent` — optional `--gpt` uses OpenAI for form decisions; telemetry timing still from calibrated simulator.

### 3. Benchmark validation

```bash
npm run test:personas          # default N=1000
npm run validate:benchmarks    # latest run vs UNIQA baselines
node scripts/validate-benchmarks.mjs --run <runId>
node scripts/validate-benchmarks.mjs --real-dir path/to/real/sessions
```

`summary.json` includes `benchmarkValidation` with per-gate deltas and tolerance flags (±5% gates, ±2% conversion).

### 4. Larger N (1000+)

`run-tests.mjs` defaults to `--n 1000` for stable aggregate statistics. Use `--n 3000` for tighter confidence on gate rates.

## Recommended workflow

1. **Profiles:** `npm run test:personas -- --n 100 --seed 1`
2. **System prompts:** `npm run persona:prompts -- --run <runId>`
3. **Interactive agent (CLI):** `npm run agent:interactive -- --run <runId> --limit 5 --verbose`
4. **Analyze drops:** `npm run agent:analyze -- --run <runId>`
5. **Validate sim stats:** `npm run validate:benchmarks -- --run <runId>`

### Form validation (interactive agent)

The CLI agent uses the same [`validateStep()`](src/logic/form.js) rules as the web form Continue button. Invalid actions stay on the same step; German validation errors are fed back to the LLM on the next turn. Partial field fills are allowed (mirroring incremental UI entry).

### Interactive agent trace files

Under `test-results/<run>/interactive-sessions/`:

| File | Purpose |
|------|---------|
| `<profile>.trace.json` | Full machine-readable log — every LLM input, raw output, parsed action, state effect |
| `<profile>.trace.md` | Human-readable timeline per turn + coach events |
| `<profile>.json` | Summary: outcome, coach intercept, persona analysis |
| `index.csv` / `summary.json` | Run-level aggregates (includes exitType, paused, dwellTurnCount) |
| `analysis.json` / `dropoffs.csv` / `pauses.csv` | Hard drops vs deferrals by step + reasons |

Each **turn** logs: `input.userMessage` (exact text to LLM), `output.rawAssistantText`, `output.parsedAction`, `effect` (form/step before/after), and `pageView.validationErrors` when the form blocks advance. **Coach events** between step 4→5 are logged separately.

### Exit types (interactive agent)

| Action | Meaning | Stats bucket |
|--------|---------|--------------|
| `leave` | Permanent abandon (distrust, frustration, wrong channel) | **Hard drop** in `dropoffs.csv` |
| `pause` | “I'll come back later” — deferral, not a drop | **Pause** in `pauses.csv` |
| `continue_thinking` | Hesitate on page; burns a turn without advancing | `dwellTurnCount` in session summary |
| `fill_fields` | Use profile values when you only need to verify data | Normal progression |

Prompt rules tell the LLM: use `fill_fields` with profile hints when data is available; use `pause` for deferral; reserve `leave` for genuine permanent abandon. If the model still sends `leave` with deferral phrasing (“I'll check later”), the runner reclassifies it as **paused** at runtime; legacy runs are reclassified in `agent:analyze`.

**Resume sessions** (save state and continue later) are not implemented — pauses end the session for now.

| File | Purpose |
|------|---------|
| `analysis.json` | Hard drops + pauses by step, completion rates, dwell stats |
| `dropoffs.csv` | Hard abandon counts only |
| `pauses.csv` | Deferral counts (separate from drop stats) |

```bash
npm run agent:interactive -- --run 2026-05-30T12-34-12 --limit 1 --verbose
npm run agent:analyze -- --run 2026-05-30T12-34-12
npm run agent:interactive -- --profile path/to/profile.json --prompt path/to/prompt.md
```

Requires `OPENAI_API_KEY` in `.env` and matching files in `system-prompts/`.

## Limits & next steps

To push realism further:

- Record **Playwright** sessions with real cursor events and merge with sampled profiles.
- Fit **continueProb** from production drop-off logs instead of static hypotheses.
- Train classifier on **held-out real sessions** only, not simulator output.
