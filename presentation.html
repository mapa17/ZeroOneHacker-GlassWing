System Overview

Three simulated components

Customer Simulation

From population
to concrete person

Three archetypal persona profiles — Judith, Franz, Peter — represent distinct UNIQA customer segments with survey-derived distributions.

A sampling process draws specific attribute values from those distributions: age, income, household type, channel preference, switch willingness, and more — producing a unique, concrete individual each run.

The sampled JSON profile is merged with the persona's narrative markdown to form a fully grounded LLM system prompt. The result is a simulated customer who behaves realistically for that segment.

Step 1 — Sample

Population → Individual

Draw age, income, location, insurance history, channel preferences from segment distributions. Each run produces a distinct person.

Step 2 — Combine

Profile + Narrative → System Prompt

JSON facts (highest priority) override the persona markdown, which provides tone, drop-off logic, and behavioral reasoning. Generic LLM knowledge fills any remaining gaps.

Step 3 — Simulate

LLM acts as the customer

The model reads each form step, decides an action, and responds with structured JSON — including a German-language Begründung explaining the choice.

Customer Simulator

LLM-driven
form navigation

At each funnel step the simulator receives a structured description of the current page — visible fields, current selections, validation errors, and any coach message — and responds with a single JSON action.

  • Selects coverage, tariff, add-ons
  • Fills personal data fields
  • Clicks proceed when satisfied
  • Can pause (defer) or leave (abandon)
  • Can send a direct question to the coach

Full traces are written per session: every prompt, every action, latency, parse retries, coach intercepts, and a final outcome classification.

Coach Simulator

Observing & nudging
without annoying

The coach receives background context about the three persona archetypes, their motivations, and a detailed playbook covering every funnel step.

After each customer action, the LLM coach observes the updated form state and decides whether to send a message — or stay silent.

  • Must speak when advisor routing is triggered (⚠ mandatory warning)
  • May speak when it adds clear value on high-risk steps
  • Stays silent for Franz-type personas on the clear online path
  • Always produces a persona estimate + concerns + reasoning
Parallel work streams

Three directions from the same base

Track A
A

Synthetic user reasoning

Generate rich, step-level explanations of why the simulated customer makes each decision — including internal hesitation, price sensitivity, and friction signals.

Goal → better predict drop-off moments from behavioral signals.

Track B
B

Analytics-driven persona modeling

Feed real funnel analytics into the coach so it can estimate which persona type it is observing — and calibrate when to intervene vs. when silence is the better choice.

Goal → persona-aware nudges that don't annoy friction-averse customers.

Track C
C

Full closed-loop evaluation

Run the minimal end-to-end system — customer sim, web form, and coach — in a closed loop. Measure whether the coach actually shifts completion rates vs. a no-coach baseline.

Goal → validate the architecture; integrate A & B findings afterwards.

Full loop

  • LLM customer behavior did not match historic drop-off measurements — the simulated personas complete the funnel at far higher rates than real users
  • A/B test (with vs. without coach) showed the coach pushing online completion to ~100% — clearly unrealistic
  • Both results point to the same root cause: the LLM is too compliant and too easily nudged, lacking the real-world friction, doubt, and inertia of actual customers
